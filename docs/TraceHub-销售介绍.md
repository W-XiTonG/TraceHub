# TraceHub 产品介绍（销售版）

## 1. 一句话定位

**TraceHub** 是一套开源的 **AI API 网关 / 中转平台**：把 OpenAI、Claude、Gemini、DeepSeek 等多种上游，统一收敛为 **一套 OpenAI 兼容的 `/v1` 接口**，并配套 **用户体系、API Key、分组与模型倍率、用量与计费、管理后台与营销官网**，适合自建「模型聚合 + 精细化运营」的中转站或企业内部网关。

---

## 2. 目标客户与场景

| 客户类型 | 典型诉求 | TraceHub 如何契合 |
|---------|---------|-------------------|
| **独立开发者 / 小团队** | 想一次接入多模型、少改代码 | OpenAI 兼容协议，现有 SDK/客户端多数可直接指向网关 |
| **中小企业 / 内部平台** | 要统一入口、成本与权限可管 | 用户、Key、分组倍率、用量日志、管理端一站式 |
| **准备做 AI 中转/聚合服务** | 要可运营、可扩展、可私有化 | 计费与兑换码、站点品牌化配置、Docker 一键栈、Prometheus 指标 |
| **技术型组织** | 要可控、可审计、可观测 | 密钥加密存储、审计日志、健康检查与 `/metrics` |

---

## 3. 商业价值（核心卖点）

1. **统一接入，降低集成成本**  
   下游只对接 **OpenAI 风格 API**；上游可以是 OpenAI 协议、原生 Claude、原生 Gemini 等，由网关完成协议与流式输出的对齐。

2. **可运营的「商业化骨架」**  
   用户注册登录、API Key（哈希存储）、余额与用量、**兑换码**、分组与模型倍率等，支撑「拉新—转化—留存」的基础运营闭环。（在线支付等能力见项目路线图。）

3. **调度与计费可解释、可调参**  
   按分组与模型筛选渠道、**加权随机**路由；可选 **Redis 粘性会话**；计费侧支持 **Token 估算与扣减**、**分组 / 用户 / 单模型** 相关倍率参与计价；并支持 **全局免计费模型** 与分组级计费开关等灵活策略。

4. **安全与合规友好设计**  
   上游渠道密钥 **AES-GCM 加密存储**；管理端敏感操作 **审计日志**；可选 **登录图形验证码**、**邮件验证码登录/注册**；`/metrics` 可配置 Bearer 保护。

5. **部署形态灵活**  
   支持 **Docker Compose 一体化**环境；前端构建产物可由 **Go 单进程托管 SPA**，适合轻量上线。

## 4. 功能亮点（当前版本已实现）

### 4.1 网关与协议兼容

- **`POST /v1/chat/completions`**：支持 **SSE 流式**；OpenAI 兼容上游可直接转发。  
- **原生 Claude / Gemini 渠道**：将上游流式结果转为 **OpenAI 风格的 `chat.completion.chunk`**，下游集成成本低。  
- **`GET /v1/models`**：返回对用户可用的模型列表。  
- **安全默认**：可配置拦截 `/v1` 下部分 **OpenAI 账号/控制台类路径**，降低误暴露风险。  
- **可选透传**：按白名单透传更多 `/v1/*`（默认关闭），满足进阶扩展。

### 4.2 智能路由

- 按用户 **分组 + 模型** 筛选渠道；**优先级 + 权重** 随机选择。  
- **可选 Redis 粘性会话**：同一会话尽量固定上游，改善连续对话体验。

### 4.3 计费与额度

- **Token 估算与实际用量** 驱动的额度扣减。  
- **分组倍率、用户维度、单模型倍率** 组合计价。  
- **全局不计费模型** 与分组覆盖；不计费仍可记录用量日志。

### 4.4 用户侧

- **注册 / 登录（JWT）**、修改密码。  
- **API Key** 管理；Key **哈希存储**。  
- **余额与用量**、**兑换码兑换**。  
- **邮件验证码**（SMTP 可配置）；可选 **简中 / 繁中 / English** 邮件策略。  
- **登录图形验证码**（依赖 Redis 时可开启）。

### 4.5 管理后台

- **用户与渠道**管理；渠道密钥 **加密落库**。  
- **分组与模型倍率**、**调用日志**查询。  
- **兑换码批量生成**与核销。  
- **审计日志**。  
- **站点与品牌**：版本号、运营方展示名、CORS、新用户默认额度、注册推广文案等可配置；支持本地上传品牌图标。

### 4.6 前端

- **营销官网**：Hero、模型展示、价格与 FAQ。  
- **用户控制台**、**管理后台**。  
- 多语言文案支持（简中 / 繁中 / English 等）。

### 4.7 可观测性与运维

- **`/health`、`/ready`**。  
- **`/metrics`（Prometheus）**。  
- 配置集中 YAML，便于多环境发布。

## 7. 定价与「倍率」沟通建议（运营附录）

- **对客户**：优先讲清 **最终单价与计费规则**（如每百万 token 对应额度/人民币）；可用「不同分组不同折扣」表述，不必逐条暴露后台倍率数字。  
- **起步调价**：在已覆盖上游成本与运维成本的基准上，拉新阶段分组倍率常见试水区间为 **0.9～0.95**；再低建议配合限时活动或兑换码，避免长期全站亏损。
