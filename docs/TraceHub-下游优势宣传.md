# TraceHub · 面向下游（调用方）的核心优势

**迹径 TraceHub** 是一套 **OpenAI 兼容的 AI API 统一网关**。对 **下游**（接入方：应用、Agent、SaaS、内部工具）而言，价值可以概括为：**少写集成、少背运维、成本可算、协议不变、能力可扩**。

---

## 一句话

> **只改 Base URL 和 API Key，原有 OpenAI SDK / 客户端继续用；背后多模型、多线路、路由与计费由网关代劳。**

---

## 1. 接入成本极低：一套协议走天下

| 下游痛点 | TraceHub 给什么 |
|---------|----------------|
| 每家模型一套 SDK、一套鉴权、一套流式格式 | **统一 `/v1` OpenAI 风格接口**，对话、模型列表等与生态习惯一致 |
| 换模型要改代码、改配置 | 请求里改 **`model` 参数** 即可；支持 **模型别名**，对外名称稳定、背后换线对你透明 |
| 从 OpenAI 迁出成本高 | **迁移成本 ≈ 两行配置**：`baseURL` + `apiKey`，HTTP 客户端、LangChain、Cursor 类工具多数可直接复用 |

**结果**：研发团队把时间花在产品与 Prompt，而不是维护「N 家厂商 × M 套适配器」。

---

## 2. 调用体验稳定：流式、工具调用、多模态一条链路

- **SSE 流式对话**：完整支持；多上游流式在网关侧 **统一为 OpenAI 风格 `chat.completion.chunk`**，客户端解析逻辑不用按厂商分叉。
- **能力矩阵覆盖广**（以运营/部署配置为准）：对话、补全、Embeddings、图像生成、音频（语音/转写/翻译）、视频任务、Realtime 通话等，都在 **同一套 `/v1` 体系** 下扩展。
- **工具调用 / 多模态**：按 OpenAI 兼容请求体传递即可，无需为每条线路单独造轮子。

**结果**：做 Agent、Copilot、客服机器人时，**协议层一次定型**，模型选型变成配置问题。

---

## 3. 可靠性由网关兜底：你只关心「能不能答」

下游不必自己实现「Key 池轮换、5xx 重试、429 避让」——平台侧提供：

- **健康准入**：异常线路自动退出选路池。
- **自动故障转移（Failover）**：网络失败、5xx、429 等可在策略内 **换渠道重试**（有上限；流式已输出则不再切换，避免破坏协议）。
- **多通道池化 + 权重/优先级**：同模型多条线路分散压力，或按运维策略「先 A 后 B」。
- **粘性会话（可选）**：长对话、工具链场景下 **同会话尽量固定线路**，上下文更连贯；失效后自动回退普通选路。

**结果**：业务代码只打 **一个稳定入口**，线路抖动由网关吸收，**感知上的可用性更高**。

---

## 4. 成本可预期、可对账：透明计费，多种计价方式

- **按 Token 精确计量**：输入/输出分开计价，规则在控制台可对齐说明。
- **灵活倍率**：分组、用户、单模型维度策略，便于「普通价 / 会员价 / 内测价」分层。
- **按次计费与混合模式**：除纯 Token 外，支持 **按请求扣费**、**混合保底/结算** 等模式，更适合图像、视频、固定单价类 API。
- **免计费模型（可配置）**：指定模型联调、灰度时可 **不扣额度**（仍可记日志），降低试错成本。
- **调用日志**：时间、模型、Token、费用、状态码可追溯，便于 **成本分析、问题定位、商务对账**。

**结果**：财务与研发能用 **同一套数据** 说话，避免「账单对不上、不知道哪条业务在烧钱」。

---

## 5. 安全边界清晰：密钥不上游、风险不外泄

- 下游只持有 **平台下发的 API Key**；真实上游渠道密钥 **加密存储在服务端**，不进你的仓库、不进客户端。
- 用户 Key **哈希保存**；管理端敏感操作可 **审计留痕**。
- 可默认 **拦截云端控制台类 `/v1` 路径**，降低误把「账号管理 API」暴露给终端的风险。
- 可选：邮件验证码登录、图形验证码、指标接口 Bearer 保护等（依赖运营配置）。

**结果**：适合 **多租户 SaaS、企业内部统一出口**——权限与密钥集中治理，应用侧攻击面更小。

---

## 6. 可观测、可扩容：对接你现有运维体系

- **`/health`、`/ready`**：容器/K8s 探针友好。
- **`/metrics`（Prometheus）**：QPS、延迟、错误率可接入现有监控告警。
- 网关 **无状态水平扩展**：流量增长时加实例 + 负载均衡即可。
- 技术栈 **Go 高并发转发**，面向 API 场景低延迟优化。

**结果**：下游团队把 TraceHub 当作 **标准基础设施组件** 接入，而不是黑盒脚本。

---

## 7. 控制台与生态：不只是 API，还有运营闭环

- **官网 + 用户控制台**：注册、创建 Key、查余额与用量、兑换码、改密等 **自助闭环**。
- **多语言界面**（简中 / 繁中 / English）：跨区域协作友好。
- **分组默认模型、CORS** 等：减少 Web/H5 直连与漏传 `model` 导致的失败。
- **开源（MIT）+ Docker Compose**：既可 **用托管平台**，也可 **私有化/二次品牌化**，交付形态灵活。

**结果**：从 **个人开发者试调到企业内网网关**，同一产品骨架都能承接。

---

## 8. 谁最适合作为下游接入方？

- **产品 / 研发团队**：要在应用里快速 **A/B 多模型**，又不想维护多套集成。
- **Agent / 自动化平台**：要强依赖 **流式 + Tool Calls + 稳定 Base URL**。
- **SaaS 厂商**：需要 **统一出口、统一计量**，把 AI 成本摊到租户或项目。
- **初创与项目制交付**：要 **可预期单价 + 可导出日志**，支撑报价与复盘。

---

## 9. 三步开始（下游视角）

1. **注册** → 控制台创建 **API Key**（仅创建时完整展示，请妥善保存）。
2. 将客户端 **`baseURL`** 指向 TraceHub 网关（常见为 `…/v1` 路径，以接入文档为准）。
3. **`Authorization: Bearer <平台 Key>`**，按需设置 **`model`**，即可与原有 OpenAI 兼容代码联调。

余额不足时可能返回 **HTTP 402**，便于程序侧做充值引导，语义清晰。

## 宣传语（可直接用于海报 / 落地页）

**主标语**

> **多模型，一条链路 —— OpenAI 兼容，一次接入。**

**副标语（任选）**

- 改两行配置，不换开发习惯。
- 路由、Failover、计费、日志，网关全包，你只写业务。
- Token 透明、按次可配、日志可对账，AI 成本看得见。
- 流式统一、工具调用即用，Agent 上线更快。
- 开源可私有化，托管可即开即用。

**电梯演讲（约 30 秒）**

TraceHub 把多家大模型收敛成 **一套 OpenAI 兼容 API**。下游不用为每个厂商写适配：换 Base URL 和 Key，SDK 照旧；换模型只改参数。网关负责 **多线路调度、故障转移、流式格式对齐、Token/按次计费与调用日志**，还有控制台与可选私有化部署。团队专注产品，集成与运维复杂度交给平台。
