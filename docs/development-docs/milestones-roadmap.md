# TraceHub 项目里程碑与开发路线图

**版本**：V1.0  
**更新时间**：2026-05-09  
**参考项目**：Sub2API、New API

---

## 一、开发策略总览

### 1.1 总体原则

1. **不减配**：所有功能必须达到产品文档和 Sub2API 对标的功能水平
2. **MVP 优先**：先跑通核心链路，再逐步叠加功能
3. **可增量交付**：每个 Phase 都能独立部署和验证
4. **前后端并行**：Phase 内前后端可同步开发

### 1.2 功能来源映射

| 来源 | 功能项 | Phase |
|:---|:---|:---:|
| **产品文档** | 官网、控制台、API 网关、管理后台 | Phase 1~3 |
| **Sub2API 对标** | OAuth 认证、粘性会话、多级倍率、离线兜底计费、TOTP、Turnstile、混合调度、一键升级回滚 | Phase 2~3 |
| **增强功能** | Antigravity 接入、语义缓存、插件化架构、RBAC | Phase 3 |

## 八、风险与缓解

| 风险 | 影响 | 概率 | 缓解措施 |
|:---|:---|:---:|:---|
| 上游 API 变更导致适配器失效 | 高 | 中 | 抽象适配器接口，快速适配 |
| OAuth Token 刷新逻辑复杂 | 中 | 高 | 参考 Sub2API 成熟实现，必要时内嵌代码 |
| 计费精度争议 | 高 | 中 | 逐笔日志可核验，离线兜底保证数据不丢失 |
| 高并发下限流延迟 | 中 | 中 | Redis 集群 + 本地缓存降级 |
| 大数据量日志查询慢 | 中 | 高 | 分区表 + 索引优化 + 异步导出 |
