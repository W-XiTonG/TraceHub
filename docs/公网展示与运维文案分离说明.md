# 公网展示与运维文案分离说明

面向公网访客与普通控制台用户时，应避免在营销页、页脚、仪表盘等位置暴露**部署运维细节**（具体 HTTP 路径、Prometheus、内部依赖名称等）。这些内容对自建部署者仍有价值，应放在 **README、配置示例、部署/运维文档、管理后台** 等面向运维或二次开发读者的渠道。

本文档记录已做的前台文案调整，以及运维信息仍可在何处查阅，便于后续迭代时保持一致。

## 1. 已调整的前台文案（用户向）

### 1.1 官网（`HomeView` + `part-*-home.ts`）

| 位置 | 原意（偏运维） | 调整后 |
|------|------------------|--------|
| 接入说明列表第三项 `home.integrationLi3` | 提及 Prometheus、`/metrics` 等观测与容量 | 强调 HTTPS、在控制台轮换 API Key，稳定性与容量由部署方负责，**不出现监控路径或产品名** |
| 页脚 `home.footerLegal` | 生产环境 HTTPS、密钥轮换、观测告警、Prometheus 抓取 `/metrics`、健康检查 `/health`与`/ready` | 改为**功能与规则说明 + 联系运营方**，不再列举探针路径 |

对应文件：

- `web/frontend/src/locales/part-zh-cn-home.ts`
- `web/frontend/src/locales/part-zh-tw-home.ts`
- `web/frontend/src/locales/part-en-home.ts`
- `web/frontend/src/views/HomeView.vue`（去掉对 `footerLegal`、`integrationLi3` 的路径占位参数）

### 1.2 用户控制台仪表盘（`part-*-console.ts`）

| 位置 | 原意（偏运维） | 调整后 |
|------|------------------|--------|
| `dashboard.healthDesc` | 写明「探测 `/ready`（数据库与 Redis）」 | 改为**自然语言**：网关后端与相关服务是否可正常响应，**不暴露路径与依赖栈** |

实现上仪表盘仍会请求 `/ready`（见 `DashboardView.vue`），仅**用户可见说明**不再复述技术细节。

对应文件：

- `web/frontend/src/locales/part-zh-cn-console.ts`
- `web/frontend/src/locales/part-zh-tw-console.ts`
- `web/frontend/src/locales/part-en-console.ts`

## 2. 未改动的区域（仍为运维/管理员向）

以下位置保留技术表述是合理的，**公网普通用户通常不会进入**或属于文档/配置：

- **管理后台**文案中的 `/health`、`/ready` 提示（负载均衡与探针绑定说明）— `part-*-admin.ts`
- **站内文档**中的 OpenAPI/运维端点说明 — `part-*-docs.ts`、`docs/产品文档.md`、`docs/development-docs/api-design.md`
- **仓库根 README** — `README.md`、`README.zh-CN.md` 中的 `/metrics`、`/health`、`/ready` 摘要
- **后端路由与配置注释** — `internal/server/router.go`、`configs/config.example.yaml` 等

若你希望管理后台也对「完全不懂运维的租户管理员」隐藏路径，可再单独弱化 `part-*-admin.ts` 中相关句子（当前默认仍面向会配 K8s/探针的运维）。

## 3. 自建部署者应查阅的文档（替代官网页脚职能）

| 主题 | 建议查阅 |
|------|-----------|
| HTTPS、反向代理、安全基线 | `docs/development-docs/deployment-ops.md`、`docs/development-docs/security-compliance.md` |
| `/health`、`/ready`、`/metrics` 行为与说明 | `docs/development-docs/api-design.md`、`internal/handler/health/health.go`、`configs/config.example.yaml` |
| Prometheus 与 Grafana 示例 | `docs/development-docs/deployment-ops.md`（监控章节）、`docs/产品文档.md` |

## 4. 后续维护约定

1. **官网、控制台「说明类」短句**：优先用户价值与安全习惯（HTTPS、轮换密钥），避免在一句里堆栈名与 URL 路径。
2. **路径与监控**：写在文档、README、管理端「系统配置」提示或代码注释中即可。
3. 新增多语言键时，三种区域语言（简中、繁中、英文）尽量同步更新，避免英文站仍出现旧版运维口吻。

如需在开发/预发环境单独显示「运维提示条」，可后续用环境变量（例如 `VITE_SHOW_OPS_BANNER`）控制，而不要写死在生产默认文案里。
