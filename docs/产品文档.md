# AI API 中转站产品需求文档

**版本**：V1.0
**更新时间**：2026-05-09
**技术栈**：后端 Go + Gin，前端 Web + 管理后台


## 一、产品概述

### 1.1 项目定位

智能 AI API 网关与资产管理系统，旨在为开发者和中小团队提供一站式的 AI 模型聚合服务。将来自不同 AI 服务商（OpenAI、Claude、Gemini、DeepSeek 等）的 API 统一为标准接口，实现模型调用的统一管理、智能调度与精确计费。

### 1.2 目标用户

- **个人开发者**：需要低成本、便捷地使用多种 AI 模型的独立开发者；
- **中小企业**：需要统一 API 入口、成本管控、团队协作的企业；
- **SaaS 产品**：将 AI 能力整合到自身产品中的软件服务商；
- **开源项目与初创团队**：需要快速接入 AI 能力进行产品验证的团队。

### 1.3 核心价值主张

| 维度 | 价值描述 |
|:---|:---|
| **统一接入** | 一套 API（OpenAI 兼容格式）调用所有主流模型，无需维护多套 SDK |
| **智能调度+精确计费** | 内置多账号负载均衡、自动故障转移与粘性会话，结合 Token 级别精准计费 |
| **成本优化+团队协作** | 差异化定价分组、用户级并发/速率控制与兑换码营销，并支持多用户配额分发与权限管理 |
| **安全可控** | 密钥加密存储、IP 白名单、内容安全过滤，支持私有化部署 |

> 参考：全球 API 中转服务市场 2026 年规模已突破 300 亿美元，年增速达 217%，用户对极致低延迟、99.9% 稳定性和全模型支持的需求持续增长。本项目以**透明计费+合规可控**为核心定位。

| | 优先级/权重路由 | 根据配置的权重值按比例分发请求 |
| | 故障转移 | 某渠道失败/超时时自动切换至可用渠道 |

| | 分批扣费 | 支持大请求的分批扣费与通知机制 |

| | 请求内容脱敏 | 支持对请求敏感字段（如 API Key）自动脱敏记录 |
| | 内容安全过滤 | 请求/响应通过敏感词过滤，违规内容自动拦截并告警 |

| | 优雅关闭 | 接收 SIGTERM 时完成现有请求再退出 |

### 4.4 请求处理流程

1. 客户端发送 OpenAI 格式请求；
2. Nginx 层负载均衡 + 反向代理；
3. `auth` 中间件验证 API Key 有效性并获取用户信息；
4. `limiter` 中间件检查用户速率限制与并发限制；
5. 控制器解析请求，调用服务层；
6. 路由 Selector 根据策略选择上游渠道；
7. 适配器层转换请求格式并调用上游 API；
8. 计费引擎预扣用户额度（基于输入 Token 预估）；
9. 上游 API 响应后，计费引擎根据真实 Token 使用量完成修正；
10. 记录调用日志，异步写入数据库；
11. 标准化响应格式后返回客户端。

## 七、市场策略与商业模式

### 7.1 主流商业模式选择

当前 AI 中转服务市场主要有三类商业模式：

| 模式类型 | 特点 | 优势 | 劣势 |
|:---|:---|:---|:---|
| **透明计费模式（本项目采用）** | 按实际 Token 用量精确计费，规则完全公开 | 用户信任度高，适合长期运营 | 利润空间相对透明 |
| **订阅制模式** | 固定月费包含固定额度 | 用户付费意愿稳定 | 存在额度浪费或超支问题 |
| **社交/聚合型平台** | API + 社区/增值服务打包 | 溢价空间大 | 核心价值偏离 API 能力 |

本项目**以透明计费为主线**，辅以**分组溢价、套餐包等多元化定价**，建立用户信任的同时保证合理利润。

### 7.2 差异化定价策略

- **基础分组**：按官方价的 1.0x ~ 1.2x 倍率定价（保本+微利）；
- **企业分组**：可提供 0.9x 折扣价但配合年付或高预付，锁定长期客户；
- **公益/教育分组**：针对学生和科研群体提供特惠价格；
- **兑换码营销**：通过折扣/满减兑换码促进新用户激活和裂变。

根据行业内数据，部分中转站项目月流水可达 500 万元，毛利率接近 50%，其利润来源主要是上游采购折扣与用户端定价之间的价差。

### 7.3 增长策略矩阵

- **冷启动阶段**：开放免费试用额度吸引早期用户；
- **增长阶段**：SEO/内容营销（技术博客/KOL推广）+ 开发者社区的邀请/分销奖励；
- **规模化阶段**：提供企业级 SLA、专属客服及对接合作公告。


## 八、安全与合规

| 维度 | 措施 |
|:---|:---|
| **密钥安全** | 上游渠道 API Key 使用 AES-256-GCM 加密存储，下游 API Key 哈希存储 |
| **网络安全** | 全站 HTTPS，支持双向 TLS（mTLS）企业接入 |
| **访问控制** | IP 白名单限制 + API Key 过期策略 + 多因素认证（MFA） |
| **数据安全** | 敏感字段脱敏记录，日志留存支持 180 天合规要求 |
| **内容安全** | 集成敏感词过滤接口，自动拦截违规请求/响应 |
| **审计能力** | 完整的操作审计日志、调用审计日志 |
| **合规认证** | 支持配置满足等保二级/三级要求，ISO27001 审计准备 |
| **运营韧性** | 关键服务多副本部署 + 定期自动备份 + 异地容灾演练 |

> 对于商业稳定运行，建议确保网关达到 99.9% 以上的服务可用性，同时对上游故障做自动切换、自愈逻辑。
